# Hydra Plan 3: Bindings and Guards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Folders can be bound to environments.
- `hydra shell` with no name opens the environment of the current folder.
- `git commit`/`git push`, `gh` write commands and the same commands run by Claude Code are blocked when run from a folder that belongs to another environment.

**Architecture:**
- **Pure core modules,** fully unit-tested:
  - `hydra_core::bindings`: resolution.
  - `hydra_core::bindedit`: editing `config.toml` and `.hydra` files.
  - `hydra_core::guard`: command classification, owner parsing, and the allow/warn/block decision.
- **Three thin guard entry points**, all calling the same decision:
  1. Git hook wrappers written by the git provider (`core.hooksPath`), which call `hydra guard git …`.
  2. A `gh` shim (a copy of `hydra.exe` named `gh.exe`, first on PATH).
  3. A Claude Code `PreToolUse` hook, injected into each environment's generated `settings.json`, which calls `hydra guard claude`.

  A matching `ssh` shim adds the environment's key.

**Tech Stack:** existing workspace (no new external crates).

**Spec:** `docs/superpowers/specs/2026-10-03-hydra-design.md`. The relevant sections are §4.3 (folder/env choice), §7.1, §7.1.1 and **§7.2 (revised 2026-10-04: hooks + gh shim + Claude hook)**.

## Global Constraints

- **Plan 1/2 constraints still apply:**
  - edition 2024 let-chains
  - no `std::env::set_var` in tests
  - user-visible text goes through `anstream` with the `style` helpers (errors ERROR, warnings WARN, success OK, hints DIM)
  - generated files start with a `generated by hydra` line and are ASCII
  - tests never touch the real `~/.claude`, `~/.claude.json` or `~/.gitconfig`
  - `cargo test --workspace`, `cargo fmt --all --check` and `cargo clippy --workspace --all-targets -- -D warnings` pass after every task
- **Path comparison** is case-insensitive on Windows, uses `/` separators internally, and ignores trailing slashes.
- **The guard fails open:** any internal error means allow plus a `hydra: warning: …` line on stderr. Only a positive wrong-environment or strict-owner decision blocks.
- **Block exit codes:** a block exits **1** from git hooks and the gh shim, and **2** from the Claude hook (Claude Code treats 2 as "blocked, show stderr to the model").
- **Exact block message,** with the first line in ERROR and the `->` lines in DIM:
  ```
  hydra: blocked <cmd> - this folder belongs to <bound> (<source>), this terminal is <current>
    -> open a <bound> terminal here: hydra shell <bound>
    -> or run it once anyway: hydra allow -- <cmd>
  ```
  - `<source>` is `rule <pattern>` or `.hydra in <dir>`.
  - `<cmd>` is the short command, e.g. `git push` or `gh pr create`.
- **Owner warning:**
  - `hydra: warning: <owner> isn't in <env>'s github owners [<list>]`. With `strict = true`, the same text after `hydra: blocked <cmd> - ` blocks instead.
- **Never write to the real `~/.gitconfig`.** The user's global `core.hooksPath` is only *read* (via `git config --file <user_home>/.gitconfig --get core.hooksPath`).
- **No version bump in tasks.** The controller sets `Cargo.toml` to 0.5.0 before merge (feature release).

## Review Focus

1. **A repo with existing hooks** (a `pre-commit` in `.git/hooks`, or a global `core.hooksPath`) must still run them, with the same arguments and stdin, and keep their exit code. Test: Task 5 `repo_hooks_still_run`.
2. **`pre-push` stdin** (ref lines) must reach the repo's own pre-push hook untouched. `hydra guard` must not read stdin in git mode. Test: Task 5 `pre_push_stdin_reaches_repo_hook`.
3. **Claude commands with chaining and `-C`**, e.g. `cd x && git -C ../repo push`, must be detected. Test: Task 4 `finds_git_in_chained_commands`.

5. **A broken `config.toml` or a missing hydra exe** must never block a commit. Tests: Task 5 `broken_config_allows_with_warning` and Task 5 `hook_allows_when_hydra_is_missing`.

### Task 1: Binding resolution (`hydra_core::bindings`)

**Files:** Create `crates/hydra-core/src/bindings.rs`; add `pub mod bindings;` to `lib.rs`.

**Interfaces (produces):**
```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Source { Rule(String), File(PathBuf) }      // pattern as written / folder holding .hydra
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Binding { pub env: String, pub source: Source }
impl Binding { pub fn describe(&self) -> String }    // "rule E:/work/**" | ".hydra in E:\x"
pub fn normalize(p: &str) -> String                   // "\" -> "/", trim trailing "/", lowercase on Windows
pub fn glob_path(pattern: &str, path: &str) -> bool   // both normalised; "**" = any segments, "*"/"?" within a segment
pub fn literal_depth(pattern: &str) -> usize          // leading segments without * or ?
pub fn resolve(dir: &Path, rules: &BTreeMap<String, String>) -> Option<Binding>
```

`resolve` rules:
- Normalise `dir` (absolute, as given).
- **Rule candidates:** every rule whose pattern `glob_path`-matches `dir`. The best one has the highest `literal_depth`; a tie goes to the longer pattern string.
- **File candidate:** walk from `dir` up to the root. The first folder containing a `.hydra` file wins. Parse it as TOML `env = "<name>"`; an unreadable or invalid file is ignored. Its depth is the number of segments in that folder's path.
- **Winner:** the file if its depth >= the best rule's literal depth, otherwise the rule. `None` if no candidates.

**CLI:**
```
hydra bind                     # show: "<dir> -> <env> (<source>)" or "<dir> isn't bound"
hydra bind --list              # every [bindings] rule: "<pattern>  ->  <env>"
hydra bind <env>               # bind the current folder (rule)
hydra bind <path> <env>        # bind <path> (rule)
hydra bind --file [<path>] <env>   # write <path>/.hydra (+ git exclude) instead of a rule
hydra unbind [<path>]          # remove the rule for exactly that folder, or its .hydra file
```
- clap shape: `Bind { args: Vec<String>, #[arg(long)] file: bool, #[arg(long)] list: bool }`. With 0 args it shows the binding; with 1 arg it's the env; with 2 args it's path then env; more is an error.
- `Unbind { path: Option<String> }`.
- Paths are made absolute against the current dir (`std::path::absolute`).
- `bind` validates the environment exists (`app.env_name`).
- Before adding a rule, if the folder already resolves to a *different* environment, print a WARN note: `note: <dir> was <other> (<source>); this rule overrides it for this folder`.
- Output: `bound <dir> -> <env> (rule <pattern>)`, or `wrote <dir>\.hydra (env = "<env>")`, plus `, added to .git/info/exclude` when it was.
- `unbind`:
  - Removes the rule `rule_for_dir(path)` if present, or deletes `<path>/.hydra` if present. Both can apply.
  - If neither exists, it prints: `<dir> has no binding of its own` plus, if it still resolves, `it's covered by <source>`.
  - Exits 0 in all cases.
- Writes to `config.toml` go through `bindedit` and then `hydra_core::config::load_global` validation on the new text (parse with `toml::from_str::<GlobalConfig>`) before writing. On failure, write nothing.

**Behaviour (spec §4.3):**
- **`hydra shell [<env>] [--cwd DIR]`, folder:**
  - `--cwd` if given.
  - Otherwise, if `<env>` was given, and the current folder does not resolve to `<env>`, and the environment has `home`: the expanded `home`.

- **`hydra env new <name> --home <dir>`:**
  - writes `home = "<dir with / separators>"` into the new env.toml (toml_edit insert after `color`);
  - adds the binding rule for `<dir>` through `bindedit`;
  - prints both.
- **`hydra whoami`:**
  - With no `--env` and no `HYDRA_ENV`, it uses the current folder's binding before giving the existing error.
  - It always prints a `folder` row as its last line. Shapes:
    - `folder   <cwd> -> <env> (<source>)` with `ok` if it matches the environment being shown, ERROR `MISMATCH` if not, nothing if unbound;

### Task 4: The guard decision (`hydra_core::guard`)

**Files:** Create `crates/hydra-core/src/guard.rs` (add to lib.rs).

**Interfaces (produces):**
```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Check {
    /// git commit / git push. `dir` is the effective folder (from `-C`), `remote_url` the push URL if known.
    Git { action: GitAction, dir: Option<String>, remote: Option<String> },
    /// a gh write command; `repo` is the --repo/-R value if given ("owner/name").
    Gh { label: String, repo: Option<String>, checks_owner: bool },
}
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum GitAction { Commit, Push }
impl Check { pub fn label(&self) -> String }    // "git commit" | "git push" | "gh pr create" ...

/// git argv (without "git"): Some for commit/push. Skips global options -C <dir>, -c <k=v>, --git-dir=, --work-tree=, -P, --no-pager.
pub fn classify_git(args: &[String]) -> Option<Check>
/// gh argv (without "gh"): Some for the write commands listed in spec §7.2.
pub fn classify_gh(args: &[String]) -> Option<Check>
/// Shell command line (Claude's Bash tool input) -> every guarded check in it.
pub fn checks_in_command_line(line: &str) -> Vec<Check>
/// "https://github.com/o/r(.git)", "git@github.com:o/r(.git)", "ssh://git@github.com/o/r" -> Some("o"); other hosts -> None.
pub fn github_owner(url: &str) -> Option<String>

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Verdict { Allow, Warn(String), Block(String) }
pub struct Facts<'a> {
    pub current_env: Option<&'a str>,     // HYDRA_ENV
    pub allow: bool,                       // HYDRA_ALLOW=1
    pub binding: Option<&'a crate::bindings::Binding>,
    pub owners: &'a [String],              // current env's github.owners
    pub strict: bool,
    pub target_owner: Option<&'a str>,     // resolved by the caller
}
pub fn decide(check: &Check, f: &Facts) -> Verdict
```

`decide` rules, in order:
1. `current_env` is None, or `allow` → Allow.
2. A binding exists and `binding.env != current_env` → `Block(msg)`, using the exact multi-line message from Global Constraints. It's plain text; the caller adds colour.
3. If the check carries owners (git push, or gh with `checks_owner`), `owners` is non-empty, and `target_owner` is Some and not in owners (case-insensitive) → `Block` if strict, else `Warn`, with the Global Constraints wording.
4. Otherwise Allow.

gh write commands:
- `pr` create|merge|edit|close|comment|review → checks_owner
- `repo` create|delete|edit|fork|rename → checks_owner
- `release` create|delete|edit|upload → checks_owner
- `issue` create|edit|close|comment|delete → checks_owner
- `api` with `-X`/`--method <m>` where m != GET (case-insensitive), or any of `-f`/`-F`/`--field`/`--raw-field`/`--input` → label `gh api`, checks_owner false

`--repo`/`-R` take the next argument or `=value`.

`checks_in_command_line`:
- Split on `&&`, `||`, `;`, `|` and newlines, outside quotes.
- Tokenise each part shell-style (`'…'`, `"…"`, backslash escapes inside `"`).
- Drop leading `VAR=value` tokens.
- Take the program token's basename without `.exe` (case-insensitive). `git` → `classify_git`, `gh` → `classify_gh`.
- If a part is `cd <dir>`, remember `<dir>` and apply it as `dir` to later git checks in the same line that have no `-C`.

**git provider:**
- `materialise` writes `state/<env>/git/hooks/<name>` for these names:
  `applypatch-msg pre-applypatch post-applypatch pre-commit pre-merge-commit prepare-commit-msg commit-msg post-commit pre-rebase post-checkout post-merge pre-push post-rewrite pre-auto-gc push-to-checkout sendemail-validate`

Bake it into the wrappers as `chain_dir`. When it's empty, the wrappers use `$(git rev-parse --git-path hooks)` at run time.
- **Wrapper script** (identical for every name except the guard line). Written with LF endings, generated header, `#!/bin/sh`:
```sh
#!/bin/sh
# generated by hydra - git hook wrapper for environment "<env>"
hook=<name>
hydra_exe='<absolute path of current_exe(), / separators>'
[ -x "$hydra_exe" ] || hydra_exe=$(command -v hydra 2>/dev/null)
# (guard line only for pre-commit and pre-push:)
if [ -n "$hydra_exe" ]; then "$hydra_exe" guard git "$hook" "$@" </dev/null || exit $?; fi
chain_dir='<user global hooksPath or empty>'
[ -n "$chain_dir" ] || chain_dir=$(git rev-parse --git-path hooks)
if [ -x "$chain_dir/$hook" ]; then exec "$chain_dir/$hook" "$@"; fi
exit 0
```
  The guard runs with `</dev/null`, so `pre-push`'s stdin stays for the repo hook. Because the wrapper uses `exec`, the repo hook's exit code is the result.
- Single-quote escaping for the baked paths (`'` → `'\''`).

**`hydra guard git <hook> [args…]`** (hidden subcommand):
- Never reads stdin.
- Effective folder: the process's current dir. git runs hooks at the work-tree root, which is fine for binding resolution.
- `current_env = HYDRA_ENV`, `allow = HYDRA_ALLOW == "1"`.
- Load global config and env config **fail-open**: on error, print WARN `hydra: warning: guard skipped (<reason>)` and exit 0.
- Hook to check:
  - `pre-commit` → `Check::Git { Commit }`.
  - `pre-push` → `Check::Git { Push, remote: Some(args[1]) }`; target owner = `github_owner(args[1])`.
  - Anything else → exit 0.
- Owners and strict come from the current env's `[github]` (if any).
- Verdict:
  - Block → print the message (first line ERROR, `->` lines DIM) to stderr and exit 1.
  - Warn → print WARN to stderr and exit 0.
  - Allow → exit 0.
