# hydraui GPUI spike — 2026-10-17

**Decision:** GO — on Windows 11 a GPUI window rendered a pwsh pane through `alacritty_terminal` and ConPTY with colour, input, resize and fast output, and `gpui-component` built and rendered in the same window.

| Criterion | Result |
|---|---|
| Window + coloured prompt | PASS. The window opened and showed `PS C:\Users\davoc>` in Cascadia Mono, crisp at 200% DPI. PSReadLine syntax colours rendered (yellow commands, blue strings, grey parameters, green variables), and so did `Get-ChildItem` colours (green `.exe`/`.bat`) and `[Console]::ForegroundColor` (SGR `38;5;9`). Checked by screenshot. |
| Input (typing, arrows, Ctrl+C) | PASS. Typing, Backspace, Left×4 then an insert (`yyyyX` → `Zyyyy`) and Enter all worked. Ctrl+C stopped `Start-Sleep 30` and the prompt came back. `Get-ChildItem C:\Windows` scrolled. Long input wrapped correctly. Checked by screenshot and log. |
| Resize | PASS. With the window at 1200×700 px, the log showed `resize -> 70x14` and `$Host.UI.RawUI.WindowSize` printed `70 14`. Resizing in the middle of a 20k-line flood re-laid the grid out without corruption. |
| 20k lines < 3 s, responsive | PASS. From the Enter key to the frame showing `line 20000`: 1.97 s (clean run), 1.97 s (with a resize during the run) and 1.13 s (first run). About 120 frames painted in 1.97 s (around 60 fps), and the resize during the run was handled about 0.4 s after Enter. Measured from the spike's own log. |
| Build time / exe size | A clean release build, all deps included, took 4 min 50 s. An incremental rebuild of the spike crate took 6.5 s. The release `.exe` is 19.2 MB. No crashes. The only rendering glitch: the gpui-component button uses the light theme. |

**Pin:** gpui = crates.io `gpui-pre =0.3.9` (snapshot of zed@93d7456; depend as `gpui = { package = "gpui-pre", version = "=0.3.9" }`) plus `gpui_platform = { package = "gpui-pre-platform", version = "=0.3.9", features = ["font-kit", "runtime_shaders"] }`; gpui-component = `=0.7.3` (builds and renders against gpui-pre 0.3.9; NOT against gpui 0.2.2); gpui-terminal = not reusable as a dependency: 0.1.0 targets gpui 0.2.2 and alacritty_terminal 0.25.1, which can't share types with gpui-pre 0.3.9. Its MIT/Apache source (`input.rs` keystroke→bytes, `render.rs` cell batching) is a useful reference to port; alacritty_terminal = 0.26.0; portable-pty = 0.9.0.

**Notes for plan 3:**
- **The GPUI ecosystem moved.** `gpui-component` 0.7.x is part of "GPUI Kit" (longbridge) and pins `gpui-pre =0.3.9`, not `gpui` 0.2.2. The app needs `gpui_platform::application()` from `gpui-pre-platform`, not `Application::new()`. Another option is the single `gpui-kit = "=0.7.3"` crate, which re-exports gpui, its platform crate and the components. It also has an optional `gpui-fast` backend; the spike did not test it.
- **Boilerplate that worked:** `gpui_platform::application().run(|cx| { gpui_component::init(cx); cx.open_window(opts, |window, cx| { let v = cx.new(|cx| View::new(window, cx)); cx.new(|cx| gpui_component::Root::new(v, window, cx)) }) })`. `window.focus(&handle, cx)` takes `cx` in this version.
- **Rendering approach:** one `canvas()` element. In prepaint, measure the cell by shaping `"M"` (width; height = (ascent+descent)×1.2), work out cols/rows from the bounds, resize the `Term` and `MasterPty` if they changed, and build one string plus `TextRun`s per row from `renderable_content().display_iter`. In paint, draw background quads, a block cursor, then `shape_line(text, size, runs, Some(cell_w))` and `.paint(..)`. Passing `force_width = Some(cell_w)` keeps the grid aligned. Wide CJK glyphs would be squeezed into one cell, so plan 3 must handle `WIDE_CHAR` properly.
- **Wakeups:** the reader thread does `parser.advance` under `FairMutex` and sets an `AtomicBool`. A `cx.spawn` loop with an 8 ms `background_executor().timer` polls the flag and calls `cx.notify()`. That's enough for about 60 fps under flood. A channel-driven wakeup would cut idle polling.
- **ConPTY must get its DSR replies.** The `EventListener` must write `Event::PtyWrite` back to the PTY (ConPTY sends `ESC[6n` at startup). The spike does this. Without it pwsh startup stalls.
- **Inherited `NO_COLOR` turns off pwsh's VT colour.** The spike inherited `NO_COLOR=1` from the agent shell, and `Write-Host -ForegroundColor` and raw `` `e[32m `` output came out plain. Console-API colours and PSReadLine still worked. hydraui should decide whether to strip `NO_COLOR` from pane environments.
- **Keys:** `KeyDownEvent.keystroke.{key,key_char,modifiers}`. The spike maps named keys (enter/backspace/arrows/home/end/pgup/pgdn/del/tab), Ctrl+letter → 0x01–0x1a, and Alt+key → ESC+key, and falls back to `key_char`. Ctrl+C as `0x03` interrupts pwsh through ConPTY. There's no IME/`InputHandler` yet; plan 3 should add one for non-ASCII input.
- **Not exercised:** mouse selection, copy/paste, scrollback UI (the wheel calls `scroll_display` but wasn't tested), cursor blink, the gpui-component dark theme (the button rendered with the light theme), and the `gpui-fast` backend.
