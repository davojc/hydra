App guide · Windows 11

hydraui, the desktop app.

hydraui is a terminal app built around hydra's environments. Every tab runs in one, coloured to match, with that environment's logins already in place. Around the terminals it adds what you reach for while working: a file tree that shows git changes, a pane for reading and editing files, quick open and search, and each environment's accounts in the status bar.

Download the installer hydra + hydraui

Portable: hydraui.exe · hydra.exe

Install and first start

Run the installer: it installs hydraui and hydra for you alone, with no admin prompt, puts hydraui in the Start menu and hydra on your PATH. Prefer a single file? The portable hydraui-x86_64-pc-windows-msvc.exe from the latest release runs from anywhere and doesn't need hydra.exe. Either way hydraui reads and writes the same ~/.hydra folder as the CLI, so environments made with either show up in both.

The first time, hydraui opens a tab in your home folder. With no environments yet, it asks you to name one and creates it, as hydra env new does. From then on hydraui starts on a page of your recent layouts: pick one, or New window for a plain terminal. A window saved as a layout keeps its file up to date as you work (the tabs, their folders and splits, the file tree and the files in each file pane); an untitled window isn't kept when you close it.

A new tab (Ctrl+T, or + in the tab strip) opens in the focused terminal's folder. Its environment is the one bound to that folder, else default_env from the settings, else you pick one:

No folder guard in the app. A hydraui terminal gets exactly the isolation hydra shell gives, with one exception: it skips the CLI's folder guard. A push to the wrong account fails on its credentials anyway. If a tab's environment differs from the folder's binding, the pane shows a warning badge.

Tabs and splits

Each tab is tinted with its environment's colour (color in its env.toml). Inside a tab, terminals form a split tree you can resize by dragging the dividers.

  • Ctrl+Shift+D splits right and Ctrl+Shift+E splits down. The new terminal has the same environment and current folder as the one you split.
  • Alt+Arrows move between panes; Ctrl+Tab and Ctrl+Shift+Tab move between tabs; Ctrl+W closes the focused pane.
  • Selecting text copies it, with a brief "Copied" label. Ctrl+Shift+V pastes and Ctrl+F finds in the scrollback.
  • Scrolled up into the history, a ↓ button appears at the bottom right and jumps back to the latest output.
  • Tab and Shift+Tab go to the shell, so PowerShell's completion cycles through matching folders and files.
  • Right-click a tab to restart its terminals (in the folders they were in, so an edited env.toml applies; it asks first if a command is running), save it as a group file, or close it.

The status bar shows the focused terminal's environment, its tools with a ✓ or ✗, the git branch and changes (⎇ main · +1 ~2 ?1) and the current folder. If an environment can't start (a missing SSH key, a secret that isn't stored), the pane shows hydra's error and how to fix it, with Retry.

File tree and git

Ctrl+B shows the file tree, rooted at the focused terminal's current folder; it follows you as you cd. It respects .gitignore and updates as files change.

  • Click a file to open it in the tab's file pane.
  • Ctrl+click a file to type its quoted path at the terminal's cursor.
  • Double-click a folder to cd there, when the shell is at its prompt.

In a git repository, files show their status: M modified in yellow, A added and ? untracked in green, D deleted in red, ignored files dimmed. A folder that holds changes gets a dot. Right-click a changed file and choose Show changes for a side-by-side diff against the last commit:

The file pane

Opening a file splits the tab: the terminal on the left, the file pane on the right, with a tab per open file.

  • Raw is an editor with syntax highlighting, line numbers and find. Ctrl+S saves, keeping the file's line endings and encoding, so a save changes only what you edited.
  • Rendered shows Markdown as a page. Markdown files open rendered; the header switches between the two. Links open in your browser, and images load only from local files.
  • OpenAPI 3 specs (.yaml, .yml, .json) open as API docs: endpoints grouped by tag, each with its parameters, request body and responses, and schemas you can unfold. A filter finds endpoints by path, method, summary or operation id. Raw shows the file, and your edits show up in the docs as you type; if an edit breaks the YAML, the docs say which line, with Go to line.
  • Open in editor hands the file to your editor (editor in the settings, else Windows' default).
  • If the file changes on disk it reloads; if you have unsaved edits you get Reload or Keep mine. Closing a file with unsaved edits asks first.
  • Files over 5 MB and binary files aren't shown, with Open in editor instead.

Finding files

All three search the focused terminal's folder and respect .gitignore.

Clickable paths

Hold Ctrl over terminal output and a path under the mouse is underlined; Ctrl+click opens it at its line. Compiler errors, test failures and grep -n output all work: src/main.rs:42, src/main.rs:42:7, src\main.rs(42,7), even when a long path wraps onto the next row. Web links open in the browser the same way.

Quick open Ctrl+Shift+O

Type a few letters of a file's name; matches are ranked so consecutive letters, word starts and the file name count most. name:42 opens at line 42.

Search in files Ctrl+Shift+F

Results appear as you type, as file:line and the line. Aa matches case and .* searches with a regular expression. Enter opens the file at the match.

Accounts

The status bar lists the focused environment's tools, each with a ✓ when its login matches and a ✗ when it's missing or wrong. Click the environment's name for the details, checked again as it opens:

  • Add account… turns a tool on for the environment, as hydra add does. Tools that only need a sign-in (Claude Code, GitHub, Azure, Google Cloud, Codex, Google Workspace) sign in straight away in a new tab; git, AWS, Gemini and Kubernetes ask for their settings first.
  • Use from… on a tool borrows another environment's login for it, so you sign in once and use it in both.
  • A borrowed login says which environment it comes from.

Sets

A set is a project's tabs written down: which environments, folders, splits and startup commands. Put it in ~/.hydra/hydraui/sets/ and it appears in the launcher; loading it opens all its tabs under one group header, and unloading it closes them (asking first if something is still running).

~/.hydra/hydraui/sets/client-a.toml
env = "work"                    # every pane's environment unless it says otherwise
cwd = "E:/work/client-a"

[[tab]]
title = "api"
cwd = "api"                     # relative to the set's cwd
layout = { split = "right", ratio = 0.6, panes = [
  { command = "claude" },
  { split = "down", panes = [
      { command = "npm run dev" },
      { },                        # a plain shell
  ] },
] }

[[tab]]
title = "infra"
env = "personal"
command = "terraform plan"
  • A pane's environment comes from the pane, then the tab, then the set, then the folder's binding. A set that can't resolve one doesn't open, and says which pane.
  • A layout node can be a file pane instead: files = ["README.md"] opens those files beside the terminals.
  • If a loaded set's file changes, its header offers reload. Several sets can be open at once; tabs you open by hand sit in the Loose group.

Layout and group files

You don't have to write sets by hand: save what's open instead.

  • Group file: tabs in the set format, with their splits, folders, environments, startup commands and file panes. Right-click a tab (Save tab as group…) or a group header (Save group…), or save every Loose tab from the launcher. Save it into the sets folder and it becomes a set.
  • Layout file (*.hydraui): the whole window, meaning its open sets, Loose tabs and file tree. Each window has one layout, named in its title bar; the name's ▾ menu has Save layout as…, Open layout file…, Recent and Reveal in Explorer. Once saved, the window keeps the file up to date. Opening a layout in a window that already has one opens a new window; opening one that's already open brings its window forward, so two windows never write the same file. With the installer, double-clicking a .hydraui file opens it. Older *.hydraui.toml files are converted when you open them.

A group file is a snapshot: the open tabs don't change. Scrollback and running programs aren't saved in either kind of file.

Settings

hydraui's own settings live in ~/.hydra/hydraui/config.toml. Every key is optional, and a mistake in one is reported without costing you the rest. Reload config in the launcher applies changes without restarting.

~/.hydra/hydraui/config.toml
font = "Cascadia Mono"          # the default
font_size = 14
theme = "dark"                   # or "light": hydraui's own controls
default_env = "work"             # for new tabs in folders nothing is bound to
default_shell = "pwsh"           # or "bash"
editor = "code"                  # for Open in editor

[colors]                          # the terminal's colours, #rrggbb
background = "#0b1116"

[keys]
split_right = "ctrl-alt-d"

[colors] also takes foreground, cursor, selection and palette, a list of the 16 ANSI colours.

Updates

hydraui checks GitHub for a new release when it starts and every six hours after. When there is one, its title bar shows Update hydra version:

  1. Clicking it downloads hydraui.exe and, if it finds your hydra.exe (next to hydraui, or on your PATH), that too, and checks both against the release's SHA-256 checksums. It won't update while a hydra command is running.
  2. Nothing is replaced until everything has downloaded and checked out; if replacing one fails, the other is put back.
  3. The button becomes Restart to finish. Restarting reopens your layout (an untitled window is saved first), but stops what's running in it, so it's always your call.

Builds you compile yourself never offer updates.
