Early release · Windows 11

One terminal per identity.

hydra opens terminals inside named environments. Each one has its own Claude Code account, GitHub login, git author and SSH key, cloud logins and secrets. A terminal stays in its environment, and none of them can quietly use another's account.

What hydra does

Most command-line tools read their login and settings from a folder you can move with an environment variable. Claude Code uses CLAUDE_CONFIG_DIR, the GitHub CLI uses GH_CONFIG_DIR, git uses GIT_CONFIG_GLOBAL. hydra keeps a separate set of those folders for each environment and starts your shell with them already set.

work · pwsh
[work] PS> gh api user --jq .login
work-user
[work] PS> git config user.email
work@example.com
personal · bash
[personal] $ gh api user --jq .login
my-username
  • Stop identity mix-ups. Commits and pushes always use the environment's author, SSH key and GitHub login.
  • Run Claude Code on several accounts at once. Each environment has its own Claude sign-in, usage limits and history. Your skills, plugins, settings and MCP servers stay shared.

Install and update

Download hydra-x86_64-pc-windows-msvc.exe from the latest release. Rename it to hydra.exe and put it in a folder on your PATH. Then create hydra's home folder:

PowerShell
PS> hydra init
created C:\Users\you\.hydra\config.toml

From then on, hydra update fetches the latest release and checks its SHA-256 checksum before replacing itself. hydra update --check only reports. It won't update while another hydra terminal is open.

PowerShell
PS> hydra update
hydra 0.4.0 is installed; 0.4.1 is available
updated to 0.4.1

To build from source instead, install Rust from rustup.rs, then git clone https://github.com/davojc/hydra.git and cargo build --release.

Walkthrough: two accounts, GitHub and Claude

This sets up a work and a personal environment, each with its own GitHub account, Claude account, git author and SSH key.

Step 1One SSH key per GitHub account

GitHub won't accept the same key on two accounts. Add each .pub file to the matching account under Settings → SSH and GPG keys.

PowerShell
ssh-keygen -t ed25519 -f $HOME\.ssh\id_ed25519_work     -C "work@example.com"
ssh-keygen -t ed25519 -f $HOME\.ssh\id_ed25519_personal -C "me@example.com"

Step 2Create the environments

Each gets its own colour, and Claude is on by default.

PowerShell
hydra env new work
hydra env new personal

Step 3Turn on the tools each one uses

hydra add only writes configuration. It never runs a tool or signs you in.

PowerShell
hydra add git work --name "Your Name" --email work@example.com --ssh-key ~/.ssh/id_ed25519_work
hydra add github work --owner acme
hydra add git personal --name "Your Name" --email me@example.com --ssh-key ~/.ssh/id_ed25519_personal
hydra add github personal

Step 4Sign in inside each environment

Use each tool's own sign-in command. The terminal opens even before you've signed in, and hydra lists what's missing.

Check which account the browser is signed in to. Browser sign-ins authorise whichever account the browser is currently using. Use a private window for the second account.
work · pwsh
PS> hydra shell work
hydra: claude: not signed in - run claude auth login
hydra: github: not signed in - run gh auth login
[work] PS> gh auth login
[work] PS> claude auth login
[work] PS> exit

Repeat in hydra shell personal with your personal accounts.

Step 5Check

PowerShell
PS> hydra whoami --env work
env      work · work
claude   work@example.com (Acme)                          ok
github   work-user                                        ok
git      work@example.com                                 ok

Each terminal stays in its environment until you close it, and you can have both open at once. Run claude in each: /status shows that environment's account.

How it works

hydra starts each terminal with environment variables that point every tool at that environment's own folder under ~/.hydra/state/<env>/.

  • Nothing leaks between environments. Identity variables inherited from the terminal you started in are removed, for example GH_TOKEN, AWS_PROFILE or ANTHROPIC_API_KEY. That includes those of tools the environment doesn't use, even when one hydra terminal is started from inside another.
  • Launch fails closed. If something could make a tool fall back to another identity, hydra refuses to open the terminal and tells you how to fix it. Examples are a configured SSH key that doesn't exist, or a secret you referenced but never stored. A tool that simply isn't signed in yet doesn't block anything.
  • Secrets live in Windows Credential Manager. Config files only reference them. Values never go to disk or into hydra's output, with one exception: a gws credentials file, which is written readable by your Windows account only.

Tools

Turn a tool on with hydra add <tool> [env]. Inside a hydra terminal you can leave out the environment. hydra add with no tool lists tools and which are on; hydra remove <tool> [env] turns one off and keeps its saved logins.

Claude Code: separate accounts, shared setup

Each environment's Claude folder (~/.hydra/state/<env>/claude) is rebuilt from your existing ~/.claude every time a terminal opens. hydra only ever reads ~/.claude and ~/.claude.json.

Linked from ~/.claude

One copy; every environment sees it.

  • skills/, commands/, agents/
  • hooks/, output-styles/
  • plugins/: install once, available everywhere

Rebuilt each launch

Shared base plus this environment's changes.

  • settings.json + envs/<env>/claude/settings.json
  • CLAUDE.md + the environment's own section
  • MCP servers from ~/.claude.json, minus --mcp-exclude

Private

Never shared between environments.

  • the Claude sign-in
  • history, projects, sessions
  • the rest of .claude.json
Changes made inside Claude don't stick. If Claude edits the rebuilt settings.json or CLAUDE.md, for example with /model, hydra saves your version as .bak on the next launch, tells you, and rebuilds the file. Put lasting changes in ~/.claude or ~/.hydra/envs/<env>/claude/.

Sign-in settings are never shared. If ~/.claude/settings.json has an apiKeyHelper or an API key under env, hydra leaves it out of every environment and warns you. Running claude outside hydra keeps using ~/.claude as before.

Variables and secrets

Any other variable goes under [env] in the environment's env.toml (hydra env edit work). Values can be plain or come from a secret stored in Windows Credential Manager.

~/.hydra/envs/work/env.toml
[env]
REGION = "eu-west"
LINEAR_API_KEY = "secret:work/linear"
PowerShell
PS> hydra secret set work/linear
value: ••••••••••••••••
stored work/linear in Windows Credential Manager

For multi-line values such as JSON, pipe them in: Get-Content -Raw creds.json | hydra secret set work/gws-creds.

Commands

CommandWhat it does
hydra initCreates ~/.hydra
hydra env new|list|edit|rm|renameManages environments. rename updates secrets and saved logins too.
hydra add [<tool>] [<env>]Turns a tool on by writing its settings. Never signs in.
hydra remove <tool> [<env>]Turns a tool off. Saved logins are kept.
hydra shell [<env>]Opens a terminal in an environment. Options: --shell pwsh|bash, --cwd DIR.
hydra run <env> -- <command>Runs one command in an environment
hydra auth <tool> <env>Runs a tool's sign-in inside an environment without opening a terminal
hydra secret set|rm <env>/<key>Stores or removes a secret
hydra whoami [--env <env>]Shows which account each tool is actually using
hydra update [--check]Installs the latest release from GitHub after checking its checksum

Files

~/.hydra
config.toml          global settings
envs/<env>/          yours: env.toml, plus optional claude/ overrides
state/<env>/         hydra's: each tool's folder, sign-ins, generated config
secrets.toml         names (never values) of stored secrets

HYDRA_HOME moves ~/.hydra. Deleting state/<env> resets an environment, but you'll need to sign in again.

Troubleshooting

MessageWhat to do
hydra: <tool>: not signed inSign in with that tool's own command inside the environment's terminal.
secret work/x isn't sethydra secret set work/x
…id_ed25519_work not foundFix the key path: hydra add git work --ssh-key <path>
CLAUDE_CONFIG_DIR error when openingRemove CLAUDE_CONFIG_DIR from [env]; [claude] sets it. Then sign in again.
… is a real folder, not a linkMove anything you want to keep into ~/.claude, delete that folder, and reopen the terminal.
A Claude setting you changed disappearedYour version is in settings.json.bak. Put lasting changes in ~/.claude/settings.json or envs/<env>/claude/settings.json.
hydra is in use - not updatingClose the listed hydra terminals, then run hydra update again.
